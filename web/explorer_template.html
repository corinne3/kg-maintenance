Pitfall 4 · Choosing a model

Property graph or RDF: same facts, two worlds

Cypher · Neo4j, FalkorDB

MATCH (p:PartType {key:'ENGINE_DRIVEN_PUMP'})
      <-[:INVOLVES_PART]-(r:Report)
      -[:HAS_CONDITION]->(c:Condition)
RETURN c.label AS condition,
       count(DISTINCT r) AS reports
ORDER BY reports DESC

Provenance (source, report, supporting text) is simply a property of the INVOLVES_PART relationship.

SPARQL · rdflib, Oxigraph, GraphDB

SELECT ?condition (COUNT(DISTINCT ?r) AS ?reports)
WHERE {
  ?r kg:INVOLVES_PART kg:PartType_ENGINE_DRIVEN_PUMP ;
     kg:HAS_CONDITION ?c .
  ?c rdfs:label ?condition .
} GROUP BY ?condition ORDER BY DESC(?reports)

An RDF triple cannot carry properties: to keep provenance, each fact becomes an rdf:Statement node (reification).
